The committed integration assertion decodes the fixture and requires the exact source, normalized-sweep, and oracle-field hashes above. The normalized hash includes Mistr schema identity, site/product metadata, volume and sweep times, gate geometry, every radial's angles and timestamp, every decoded value, every detailed gate status, and every raw code.

The Rust unit test also verifies that cloning unchanged data preserves the normalized hash and modifying a raw gate changes it.

## Failure and allocation behavior

Automated tests cover:

- empty input;
- input shorter than the Archive II header;
- bounded outer-gzip expansion;
- bounded bzip2-record expansion;
- excessive record count;
- explicit legacy CTM rejection;
- distinct scaled-moment handling for synthetic raw codes `0` (below threshold), `1` (range folded), and `2+` (valid);
- arbitrary byte vectors generated by `proptest`, wrapped in an outer panic assertion;
- the verified current KTLX integration fixture when present.

The normalizer additionally rejects zero or excessive dimensions, inconsistent per-radial geometry, non-integral ranges, non-finite values, invalid site coordinates/identifier, invalid timestamps, and out-of-range angles before returning Mistr-owned data. The limits and upstream-risk rationale are recorded in [the decoder decision](../13_DECODER_DECISION.md). Property generation is the continuously runnable bounded fuzz lane in CI/local tests; the current corpus and malformed tests do not establish support for every historical NEXRAD message variant.

## Unsupported variants

- Legacy CTM/pre-LDM archives: rejected in Phase 1.
- Realtime Level II chunks before volume assembly: not accepted.
- Level III data: different adapter, later decision.
- Level II velocity: decoder path present, independent correctness acceptance pending and semantics remain base velocity.
- Historical or novel messages not represented by the fixture: unproven.
